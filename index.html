Why Dwell Time Is Lying to You

In content-heavy verticals like media, publishing, and e-commerce, dwell time is a critical signal, used as a proxy for content quality, user interest, and intent. But there's a dirty secret: raw dwell time includes every second a browser tab sat open while its owner was making coffee, in a meeting, or simply distracted.

"A three-minute session and a thirty-second session look identical if the user walked away at the right moment."

The result is a metric that systematically overstates engagement. Teams celebrate rising average session durations that are, in part, just rising rates of distraction.

What actually signals engagement?

The browser exposes a rich set of passive signals that prove a human is present and attending: mouse movements, scroll events, keyboard activity, clicks. None of these require invasive instrumentation; they're standard DOM events every browser has supported for twenty years.

The key insight is to treat engagement as a sliding window. If any activity signal arrives within the last N seconds, the user is engaged. Once the window expires without a signal, the clock stops. When activity resumes, the clock restarts.

The tab-visibility problem

A related issue: users with many open tabs. Your page may sit in the background for twenty minutes while the user reads something else. The Page Visibility API handles this: when the tab hides, the plugin fires a summary event immediately using sendBeacon, ensuring the data is captured even if the tab is killed in the background.

What this means for your data

Across typical content sites, engaged dwell time runs 40–60% of raw dwell time. The gap is larger on mobile (where users put the phone down mid-read) and on long-form content where readers pause to think.

More importantly, engaged dwell time correlates more strongly with downstream outcomes: return visits, conversions, subscription signups. Raw dwell time, in many product contexts, is measuring distraction as much as intent.

Switch to engaged dwell time. Your content quality metrics will look worse at first. That's the point: you'll be seeing them clearly for the first time.

How it works

The plugin uses the Amplitude Browser SDK's enrichment plugin interface. On setup() it registers lightweight activity listeners and starts a 1-second accumulator tick. On page exit it fires a single summary event via sendBeacon.

┌─────────────────────────────────────────────────────────────┐ │ EngagedDwellTimePlugin │ ├─────────────────────────────────────────────────────────────┤ │ Activity listeners (throttled to 500ms) │ │ mousemove · scroll · keydown · click · touchstart · wheel │ │ │ │ │ ▼ │ │ lastActivityTime = now │ ├─────────────────────────────────────────────────────────────┤ │ Tick loop (every 1 second) │ │ if (now − lastActivityTime < inactivityThreshold) │ │ engagedTimeMs += tickDelta │ ├─────────────────────────────────────────────────────────────┤ │ Exit signals (first one wins — rest are deduped) │ │ visibilitychange → hidden ─┐ │ │ pagehide ├──▶ [Engaged Dwell] Page Exit │ │ beforeunload ─┘ + amplitude.flush() │ └─────────────────────────────────────────────────────────────┘

The three exit signals (visibilitychange, pagehide, beforeunload) all call the same handler. A hasFired flag ensures exactly one event is sent regardless of how many fire together.

  • visibilitychange — primary signal on mobile; fires reliably when the app is backgrounded on iOS/Android
  • pagehide — handles back/forward cache navigation; more reliable than unload
  • beforeunload — catches desktop close/refresh cases that pagehide can miss

Quick start

  1. Include the Amplitude Browser SDK

    Via CDN or npm — no changes to your existing setup.

  2. Add the plugin file

    Drop engaged-dwell-time-plugin.js into your project and load it after the SDK.

  3. Call amplitude.add()

    One line. The plugin self-registers its listeners and starts the tick loop.

<!-- Amplitude Browser SDK -->
<script src="https://unpkg.com/@amplitude/analytics-browser@2/dist/analytics-browser.umd.min.js"></script>

<!-- Engaged Dwell Time plugin -->
<script src="engaged-dwell-time-plugin.js"></script>

<script>
  // Standard Amplitude initialisation
  amplitude.init('YOUR_API_KEY', {
    autocapture: { pageViews: true, sessions: true }
  });

  // Add the plugin — one line
  amplitude.add(
    createEngagedDwellTimePlugin({ inactivityThreshold: 30_000 })
  );
</script>

The event Amplitude receives

On page exit, a single event is fired. Both engaged_time_ms and total_time_ms are included so you can compare them side-by-side in any Amplitude chart.

{ "event_type": "[Engaged Dwell] Page Exit", "event_properties": { "engaged_time_ms": 47200, "total_time_ms": 183000, "engaged_ratio": 0.26, "page_url": "https://yoursite.com/blog/post", "page_title": "Why Dwell Time Is Lying to You", "inactivity_threshold_ms": 30000 } }

In Amplitude, chart [Engaged Dwell] Page Exit and visualise the average of engaged_time_ms broken down by page_url. Stack it against total_time_ms to immediately see which pages have the highest idle inflation.

Configuration

OptionDefaultDescription
inactivityThreshold 30000 Milliseconds of inactivity before the user is considered idle. Decrease for fast-paced UI, increase for long-form reading.
tickInterval 1000 How often (ms) the accumulator tick runs. 1 second is the recommended value.
throttleMs 500 Throttle applied to activity listeners. Prevents mousemove firing callbacks at 60fps.
activityEvents ['mousemove', 'scroll', 'keydown', 'click', 'touchstart', 'wheel'] DOM events that count as engagement signals. Remove mousemove for lower-overhead deployments.

Single-page app (SPA) support

In a SPA the page never fully unloads on navigation. Call plugin.reset() on each route change — it fires the exit event for the current page and starts a fresh count for the next one.

// React Router example
import { useEffect } from 'react';
import { useLocation } from 'react-router-dom';

function useEngagedDwell(plugin) {
  const location = useLocation();

  useEffect(() => {
    plugin.reset(); // fires exit event for previous page, resets for new one
  }, [location.pathname]);
}
Note: plugin.reset() fires the summary event for the current page before resetting — no data is lost on navigation.

Performance footprint

  • Memory: <1 KB — six primitive variables, no DOM references held open
  • CPU: One timestamp comparison per second (tick) + one per activity event after throttle
  • Network: One sendBeacon call per page exit — non-blocking, survives page teardown
  • No dependencies beyond the Amplitude SDK you already have on the page
